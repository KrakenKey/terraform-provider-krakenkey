# Contributing

> **Not yet applicable.** There is no Go module here yet, so none of the commands below work. They describe the planned workflow. The first implementation PR should add `go.mod`, the provider entry point and CI (issues #1, #2 and #5), then update this file. See the status notice in [README.md](README.md).

## Planned layout

The plan in #1 is to start from HashiCorp's [terraform-provider-scaffolding-framework](https://github.com/hashicorp/terraform-provider-scaffolding-framework) template, using `terraform-plugin-framework`, with the module path `github.com/KrakenKey/terraform-provider-krakenkey`. The Go and Terraform versions will be whatever that template and `go.mod` require at the time.

## Build

```bash
go build -o terraform-provider-krakenkey .
```

## Unit tests

Unit tests need no credentials:

```bash
go test ./...
```

## Acceptance tests

Acceptance tests create and delete real KrakenKey resources and count against plan limits. Use a test account, not production. Certificate tests also need a domain that is verified and has its `_acme-challenge` CNAME in place, so they depend on real DNS.

```bash
export TF_ACC=1
export KK_API_KEY=kk_...
go test ./... -v -timeout 30m
```

Set `KK_API_URL` to run against a non-production API.

## Local development override

To try a local build without the registry, point Terraform at the directory that contains the binary:

```hcl
# ~/.terraformrc
provider_installation {
  dev_overrides {
    "krakenkey/krakenkey" = "/absolute/path/to/directory/containing/binary"
  }
  direct {}
}
```

With `dev_overrides` set, run `terraform plan` directly. Skip `terraform init` for the overridden provider.

## Code style

- Run `gofmt` and `go vet ./...` before committing.
- Give every schema attribute a `Description`. tfplugindocs builds the registry docs from them (#22).
- Mark API keys and other secrets `Sensitive: true`. Certificate PEMs are public and do not need it.
- Registry docs under `docs/` are generated by tfplugindocs. Do not edit them by hand.

## Releases

Planned in #24 and #25: tag `vX.Y.Z`, GoReleaser builds and signs the binaries, and the Terraform Registry picks up the GitHub release. Publishing needs:

- a public GitHub repository (this one is private today),
- the provider registered under the `KrakenKey` namespace on the Terraform Registry,
- a GPG signing key added to the Registry and to the release workflow,
- a license file.
